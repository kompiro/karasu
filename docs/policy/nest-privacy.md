## 1 行で

karasu-nest が保持するのは、**投稿された `.krs` と、投稿者の GitHub 識別子**、および
サインイン中のセッションだけである。
**ソースコードを読まない。** 投稿者はいつでも自分ですべてを削除できる。

## 何を集めるか

| 何を | いつ | なぜ |
| --- | --- | --- |
| GitHub の数値 user id | サインイン時 | 投稿の帰属先。鍵として使う。GitHub が rename しても変わらない |
| GitHub の login 名 | サインイン時 | 表示用。サインインのたびに更新する |
| 投稿された `.krs`（タイトル・公開設定を含む） | 投稿時 | サービスの目的そのもの |
| セッション | サインイン時 | 本人であることの確認 |

**サインインで要求する権限（scope）は空である。** `GET /user` は権限の無いトークンでも
数値 id と login 名を返し、その 2 つで足りるので、それ以上を要求する理由が無い。

### 集めないもの

- **メールアドレス。** 要求しないし、保持しない
- **ソースコード。** サービスは repository を読まない
- **アクセス解析・広告・トラッキング目的の第三者スクリプト**

> **メールアドレスを持たない理由は、保持方針の帰結である。** 投稿物に期限が無いので、
> 期限切れを予告する必要が無く、したがって連絡先が要らない。日数で切る設計にしていたら
> 通知が要り、通知のためにメールアドレスを持つことになっていた。
> [ADR-2262](../adr/2262-nest-intake-and-completion.md) が避けた線を、ここでは越えずに済んでいる。

### 投稿物の中身について正直に書く

`.krs` は構造の記述だが、**投稿者がラベルや `description` に何を書くかはサービスが
決められない**。投稿時に資格情報の形をした文字列を検査して拒否するが、検出は形に
基づくので万能ではなく、氏名やメールアドレスを対象とする規則は無い。

したがって「投稿物に個人データは含まれない」とは書けない。**投稿者が書いたものが
そのまま公開される。**

## どれだけ保持するか

| 何を | 保持 |
| --- | --- |
| 投稿された `.krs` | **投稿者が削除するまで** |
| アカウント記録 | **アカウント削除まで** |
| セッション | **最後に使ってから 30 日**（使うたびに延びる）。ただし**発行から 90 日**を超えては延びない |

**日数ではなく条件で書いてある。** 投稿者が管理するコンテンツが黙って消えるのは、
自己管理の面を用意した目的と衝突する — 「投稿したはずの図が無い」という問い合わせを
自分で作ることになる。代わりに、削除の手段を本人の手元に置いた。

セッションだけは資格情報なので期限を持つ。**使っている限りサインインは保たれる**が、
**発行から 90 日**を超えては延びず、そこで一度サインインし直すことになる。上限を置かない
と、資格情報が自分自身を無期限に更新できてしまう。

## 誰が見られるか

- **公開の投稿**: URL を知っていれば誰でも読める。これがギャラリーの目的である
- **非公開（unlisted）の投稿**: 本人以外には配信しない。存在しない id への応答と
  **完全に同一の応答**を返す — 「この人が投稿して取り下げた」を確かめる手段にしないため

公開／非公開は投稿者がいつでも切り替えられる。

## 誰に渡るか（サブプロセッサ）

| 事業者 | 用途 | 渡るもの |
| --- | --- | --- |
| Cloudflare, Inc. | ホスティング・ストレージ | 投稿物、アカウント記録、セッション、ログ |
| GitHub, Inc. | サインイン（OAuth） | 認証のやり取りのみ。GitHub が既に持っている情報以外は渡らない |

**モデルプロバイダは居ない。** サービスは推論を行わない。

これ以外の第三者に渡すことはない。法令に基づく開示要求があった場合は、法令の範囲で
対応する。

## 権利の行使

**すべて自分でできる。** 問い合わせを待つ必要が無い。

| したいこと | どうするか |
| --- | --- |
| 投稿を見えなくする | コンソールで非公開にする（可逆） |
| 投稿を直す | コンソールで差し替える |
| 投稿を消す | コンソールで削除する |
| **全部消してアカウントも閉じる** | コンソールの「アカウント削除」。投稿・アカウント記録・全セッションが**ひとつの操作**で対象になる（完全性については「削除の限界」） |
| 投稿を手元に取り戻す | `/g/<id>?format=krs` でいつでも取得できる |

自分の投稿以外について申し立てたい場合（なりすまし・権利侵害など）は
<https://github.com/kompiro/karasu/issues> で受ける。**申し立ては公開の場に残る**ので、
公開そのものが問題になる種類の申し立てには向かないことをあらかじめ書いておく。

**発信者情報開示の請求（誰が投稿したかの開示を求めるもの）は、この窓口では受けられない。**
請求者と投稿者の双方の個人データが公開の場に出てしまうためである。**その別経路はまだ
決まっていない。** 開示に応じる手順そのものが未了であることを、隠さずここに書いておく。

## 削除の限界

Cloudflare のストレージの一覧取得は結果整合であるため、削除の直前に着地した書き込みが
最初の一覧に現れないことがありうる。そのため削除経路は**再実行できる形**にしてある。
「1 回の操作で完全性を保証する」とは書かない。
