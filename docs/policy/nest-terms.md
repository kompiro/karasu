## 1. このサービスは何か

karasu-nest は、利用者が**自分の環境で作ったアーキテクチャモデル（`.krs` ファイル）を
預かって公開・共有するギャラリー**である。

**サービスは利用者のソースコードを読まない。** モデルの作成は利用者の環境で行われ、
サービスが受け取るのは投稿された `.krs` だけである。

## 2. アカウント

投稿には GitHub アカウントでのサインインが必要である。アカウント記録としてサービスが
保持するのは **GitHub の数値 user id と login 名**だけで、メールアドレスは要求しない。

匿名投稿を認めないのは、**取り下げ請求に応じる相手と、濫用を止める手段が必要**だから
である。アカウントは、投稿の帰属先であると同時に、責任の所在である。

サインインの状態は、使い続けている限り保たれる（最後に使ってから 30 日で切れる）。
ただし**発行から 90 日**を超えては保たれず、そこで一度サインインし直すことになる。

運営者は、本規約に反する利用があったと判断した場合、事前の通知なくアカウントを
停止し、投稿を非公開または削除することができる。

## 3. 投稿されたモデルの権利

**投稿物の権利は投稿者に留まる。** 運営者はこれを譲り受けない。

投稿者は、投稿をもって運営者に対し、**サービス上でその投稿を保存・複製・表示・配信する
ための、無償・非独占の許諾**を与えるものとする。この許諾はサービスの運営に必要な範囲に
限られ、投稿が削除された時点で（バックアップからの消去に要する合理的な期間を除いて）
終了する。

投稿者は、投稿にあたって次を表明する。

- 投稿する `.krs` を投稿する権利を有していること
- 投稿が第三者の権利（著作権・営業秘密・契約上の守秘義務を含む）を侵害しないこと
- 投稿が事実に反する帰属（自分が関与していないシステムやその組織の設計であると
  名乗ること）を含まないこと

> **なりすましについて。** 「これは有名 OSS のアーキテクチャです」と誰でも名乗れる。
> GitHub のサインインが与えるのは**権限の証明ではなく責任の所在**であって、投稿内容の
> 正しさをサービスが保証するものではない。第 5 節の申し立て経路がこれを受ける。

## 4. 保証と責任の制限

**投稿されたモデルは、投稿者の理解の記述であって、設計の保証ではない。**

サービスおよび投稿物は現状有姿で提供される。運営者は、投稿されたモデルの正確性・
完全性・特定目的への適合性について、**明示・黙示を問わずいかなる保証も行わない**。
投稿物を参照して行った判断の結果について、運営者は責任を負わない。

運営者は、サービスの中断・データの消失・投稿物の公開範囲の誤りについて、法令が
許す最大限の範囲で責任を負わない。ただし運営者の故意または重過失による場合は
この限りでない。

**このサービスは個人が運営している。** 可用性の約束（SLA）は無い。

## 5. 申し立て・お問い合わせ

**GitHub Issue で受ける。** 専用のフォームやメールアドレスは用意しない。

- 窓口: <https://github.com/kompiro/karasu/issues>

この形にした理由と代償を書いておく。

- **新しい個人データが増えない。** 申し立てる側は既に GitHub アカウントを持っていて、
  こちらは何も預からない
- **対応の経緯が公開され、監査可能になる。** 同種の申し立てに対する判断の一貫性も追える
- **代償: 申し立て自体が公開される。** 「この図は当社の内部構造だ」という申し立ては、
  それ自体が情報の開示になりうる。公開が問題になる種類の申し立てには別経路が要る —
  必要になった時点で連絡先を追加する

投稿者自身による取り下げ（削除・非公開化・差し替え）は**申し立てを要さない**。
コンソール（`/console`）で本人がいつでも行える。

## 6. サービスの終了・変更

運営者はサービスを変更または終了することができる。**終了する場合は、投稿者が投稿物を
回収できる合理的な猶予を置く**。投稿物は `.krs` テキストとしていつでも取得できる形で
提供されている（`/g/<id>?format=krs`）。
