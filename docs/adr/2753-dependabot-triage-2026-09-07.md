## 背景

2026-09-07（月）の weekly バッチ。npm 8 件 + github-actions 2 件の計 10 件が起票された。
`security` ラベル付きはゼロ、`dependabot/alerts` の open も 0 件で、純粋な version update
バッチである。10 件すべて CI green・`MERGEABLE CLEAN`。
`.github/workflows/dependabot-triage.md`（週次 agentic workflow）による `[dep-triage]`
Issue や PR コメントは今回付いていないので、所見の検証ではなく一次調査として全件を辿った。

`.claude/rules/dependabot.md` に従い、bump 種別を問わず 10 件すべてを upstream まで
遡って分析した。**配布主体の乗っ取り・改ざんの兆候はゼロ**で、移行先バージョンを
脆弱範囲に含む advisory も 1 件も無かった。

判断が要ったのは 2 件で、性質が異なる。

1. **[#2740](https://github.com/kompiro/karasu/pull/2740) は生成物を部分的に書き換えている。**
   対象の `.lock.yml` は `gh aw compile` の生成物で、Dependabot は `uses:` 行だけを更新し、
   同じファイル内のメタデータと `.github/aw/actions-lock.json` を据え置いた。
2. **[#2744](https://github.com/kompiro/karasu/pull/2744)（astro）は upstream が新規パッケージを招き入れている。**
   `find-process` を、公開 17 日目・単独メンテナの fork `find-proc@0.1.0` に差し替えた。

## 理由

### 生成物への部分編集は、マージしても次の compile で消える

`.github/workflows/dependabot-triage.lock.yml` と `security-alert-sweep.lock.yml` は、
先頭に `# This file was automatically generated by gh-aw (v0.86.2). DO NOT EDIT.` を持つ
`gh aw compile` の生成物である。Dependabot はこれを普通の workflow YAML として扱い、
**`uses:` 行 10 箇所だけ**を書き換えた。結果、ヘッド側は次の状態になっていた。

| 箇所 | 値 | |
| --- | --- | --- |
| `uses:` 行（10 箇所） | `github/gh-aw-actions/setup@bc8c008a…` / `v0.87.10` | **更新された** |
| `# gh-aw-manifest` ヘッダ内の `actions[]` エントリ | `"sha":"6aab9e5b…","version":"v0.86.2"` | 据え置き |
| `# gh-aw-metadata` の `compiler_version` | `"v0.86.2"` | 据え置き |
| `.github/aw/actions-lock.json` | `"github/gh-aw-actions/setup@v0.86.2"` → `6aab9e5b…` | **PR に含まれない** |

同一ファイルの中で「マニフェストが宣言する SHA」と「実際に実行される SHA」が食い違い、
SHA pin の正本である `actions-lock.json` は旧版を指したままになる。SHA pin は
**宣言と実行が一致していること**に価値があるので、この状態は pin の意味を損なう。
加えて v0.86.2 のコンパイラが生成した本体スクリプトを v0.87.10 の setup action が
セットアップすることになり、0.86 → 0.87 の間の互換性は upstream が保証していない。

決め手は**永続しないこと**である。この diff をマージしても、次に誰かが `gh aw compile` を
回した瞬間に生成物ごと巻き戻る。入れるべきは「setup action の SHA」ではなく
「v0.87.x 系で再生成した lock 一式」なので、bump ではなく再生成として起票した。

なお action の SHA pin 自体は正しかった。`v0.87.10` の annotated tag を辿ると commit は
`bc8c008a419c5b7a29df6f5641edd35fd1c6ea85` で PR の pin と一致し、コミットは
`github-actions[bot]` の `chore: sync actions from gh-aw@v0.87.10 (#222)`（2026-08-31）である。
**却下の理由は SHA の真正性ではなく、生成物を部分的に書き換えたことにある。**

### upstream が招き入れた新規パッケージは、待っても検知の足しにならない

astro 7.2.9 は `find-process@^2.1.1` を `find-proc@0.1.0` に差し替えた。upstream の変更は
[withastro/astro#17786](https://github.com/withastro/astro/pull/17786)（commit `db7c53b`）で、
**PR を送った `@gameroman` が `find-proc` の唯一のメンテナ本人**である。
「コントリビュータが自作パッケージを広く使われる framework の依存に入れる」形なので、
供給側の確認を通常より厚めに行った。

- 2026-08-21 に作られた新しいパッケージ（astro が使うのは `0.1.0`）。README に
  `find-process` の fork と明記。
- 配布物は 5 ファイル・18 KB（`dist/index.mjs` 521 行 + 型定義 + LICENSE + README）。
  **ランタイム依存ゼロ**（元の `find-process` が連れていた `loglevel` が消える）。
- **install / postinstall / preinstall / prepare スクリプトなし。**
- SLSA provenance あり（GitHub Actions から publish）。
- 配布バンドル全文を走査した結果、**ネットワーク送信・`eval` / `new Function`・
  `process.env` 参照・`Buffer.from` によるデコード・`atob` はいずれも 0 件**。
  外部インタフェースは `node:child_process` の `exec` / `spawn` のみで、組み立てる
  コマンドは `ps ax -ww -o pid,ppid,uid,gid,args` / `netstat -tunlp` / `lsof -nP -i :<port>` /
  `netstat -ano` / `powershell.exe` と、`find-process` が元から実行していたものと同じ系統。

`astro` は `packages/docs-site` の devDependency のみで、GitHub Pages のドキュメントサイトを
ビルドするときにしか動かない。karasu の配布物（npm パッケージ・VS Code 拡張・Pages app）には
入らない。

保留しなかったのは、**待っても得るものが無い**からである。astro 7.2.4 以降すべてが
`find-proc` を持つので「様子を見る」は patch 更新を無期限に止めることを意味し、
一方 0.1.0 は既に astro 経由で広く配られているため karasu が個別に待っても改ざん検知の
役には立たない。

### 供給側と advisory の確認結果

`published` は 10 件すべて 7 日以上前で、cooldown（[ADR-784](784-update-dependencies-20260421.md)）は
満たされている。最も新しい `lucide-react` がちょうど 7 日だった。メンテナ一覧の異常
（新規 publisher・所有権移管・アカウント改名）は 10 件いずれにも無い。install スクリプトを
持つのは `lefthook` の `postinstall` だけで、従前と同一である。`vscode-language*` の
provenance が none なのは従来どおりで、代わりに `prepublishOnly` が
`⛔ Can only publish from a secure pipeline ⛔` で人手 publish を塞いでいる。

advisory は `gh api /advisories?ecosystem=npm&affects=<pkg>` で全パッケージを引いた。
**移行先バージョンを脆弱範囲に含むものは 1 件も無い** — `astro` は 5.x 以下、
`svgo` は `= 4.0.0`、`playwright` は `< 1.55.1`、`@anthropic-ai/sdk` は `< 0.91.1`、
`zod`（knip 経由）は `<= 3.22.2` がそれぞれ最新の脆弱範囲で、いずれも今回の移行先の外側。

`pnpm-workspace.yaml` の `overrides:` は空なので、`ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` の
失敗モード（`.claude/rules/dependabot.md`「override 付き直接依存の security update PR」）は
そもそも起こり得ない。

### 巻き込みは lock の依存エッジで確認した

解決バージョンの集合比較ではなく `pnpm-lock.yaml` の**依存エッジ**を base とヘッドで
突き合わせた（peer suffix を落として比較）。npm 8 件のうち、意図した bump 以外に動いたのは
`knip` 経由の `formatly` / `get-tsconfig` / `oxc-parser` / `picomatch` / `zod`、
`@anthropic-ai/sdk` 経由の `standardwebhooks`、`astro` 経由の `@astrojs/compiler-*` /
`satteri` / `sharp` / `js-yaml` などで、いずれも既存グラフ内の版移動である。
**バッチ全体で lock に新規登場したパッケージ名は `find-proc` の 1 件だけ**だった。

### `lsp` group は設計どおり働いた

[#2743](https://github.com/kompiro/karasu/pull/2743) は `.github/dependabot.yml` の
`lsp` group が 4 パッケージを 1 PR にまとめた結果で、protocol 版が client / server で
食い違う形は発生していない。group を入れた [ADR-2333](2333-dependabot-triage-2026-08-04.md)
以降の設定が、10.x で初めて実地で効いた回になる。

### `@playwright/test` の宣言レンジ引き上げ

[#2749](https://github.com/kompiro/karasu/pull/2749) は解決版 1.59.1 → 1.62.1 に加えて
宣言レンジの下限も `^1.49.0` → `^1.62.1` に上がる。CI は Playwright のコンテナイメージを
版で pin しておらず（`.github/workflows/*.yml` に `mcr.microsoft.com/playwright:v*` の
参照なし）、ブラウザは毎回 install されるため、required gate の Playwright は
そのまま pass した。

## 却下した案

### #2740 をそのままマージする

`uses:` の SHA 自体は tag と一致しているので、追加作業ゼロで入る。却下した理由は
**永続しないこと**で、次の `gh aw compile` で巻き戻る。加えてマニフェストと実体が
食い違った生成物が main に残り、`actions-lock.json` は旧 SHA を指し続ける。

### #2740 を close し、`.github/dependabot.yml` の `ignore` で今後も抑止する

同じ形の PR が毎回出るのを止められるが、今回の bump そのものは入らないままになる。
また `ignore` の粒度はパッケージ単位（`dependency-name`）で、`.lock.yml` に限った除外は
書けない。同じ action を非生成 workflow で使い始めたときに黙って更新が止まる。
**却下は「生成物であること」が理由なので、パッケージ単位の無視では粒度が合わない。**
[#2762](https://github.com/kompiro/karasu/issues/2762) がマージされれば `uses:` は
v0.87.10 になり、同じ PR は二度と起票されない。

### #2740 を差し替え PR として扱う

今回の判定は**却下**であって差し替えではない。差し替え PR は
「bot が作れる diff の形では正しい変更にならない」ときに**同じ bump**を別 PR で入れる手段だが
（[ADR-2474](2474-dependabot-replacement-pr-vocabulary.md)）、今回入れたいものは bump ではなく
compile 結果全体で、対象ファイルも `.md` 側のコンパイル出力に広がる。同じ bump を別の形で
入れるのではない以上、差し替えとは呼ばない。判定が却下なので `@dependabot ignore` を
検討する側に入るが、上記のとおり設定しない。

### #2744 を保留し、次の astro リリースまで様子を見る

`find-proc` が実績を積むのを待てるが、astro 7.2.4 以降すべてが `find-proc` を持つので
patch 更新を無期限に止めることになる。配布物を読んだ結果に問題が無く、露出も
docs-site のビルド時に限られるため、止める理由が立たない。

## 積み残し

**生成物を Dependabot に部分編集させ続けるか。** 今回は再生成 PR で吸収するが、
gh-aw が自身の action を上げるたび同じ形の PR が出る。`.gitattributes` は lock を
generated 扱いにしているが、それは Dependabot には効かない。除外の仕組みが要るかどうかは
再発回数を見てから判断する（[#2762](https://github.com/kompiro/karasu/issues/2762) に記載）。
