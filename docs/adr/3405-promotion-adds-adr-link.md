# ADR-3405: ADR の昇格で、新しい ADR へのリンクを足すだけの差分も張り替えと同じく Low に数える

- **日付**: 2026-10-30
- **ステータス**: 決定済み
- **関連**:
  - Issue #3405（起点。ADR-3309 の昇格 PR #3392 で見つかった）。Design Doc は書かず、合わせる側（分類器か AT の規約か）はユーザーが Issue の起票時に決めた
  - [ADR-2331](2331-adr-automerge-scope.md)（ADR PR の auto-merge 例外を差分の性質で判定する。本 ADR はその「張り替え」に「リンクの追加」を足す）、[ADR-2348](2348-at-records-point-at-issues.md)（AT は Design Doc ではなく Issue を指す）、[ADR-3286](3286-risk-based-review-tiers.md)（段階の分類器。ADR-2331 の条件はその規則になった）
  - TPL: [TPL-3286](../test-perspectives/TPL-3286-merge-eligibility-judged-on-final-diff.md)（本件の失敗モードを追記した）、[TPL-2254](../test-perspectives/TPL-2254-durable-record-points-at-durable-address.md)
  - コード: `scripts/review/tier.ts`（`isLinkInsert`、`fileTier` の昇格の分岐）

## 背景

ADR-2331 は、ADR の昇格 PR を auto-merge の例外に入れる条件を、差分の性質で決めた。新しい ADR、生成物、Design Doc の削除、そして **Design Doc を指していた参照を新しい ADR に張り替える差分**である。当時の AT は Design Doc を指していたので、昇格 PR が AT に触れるのは張り替えのときだけだった。

その後 ADR-2348 で、AT は Design Doc ではなく Issue を指すことになった。`.claude/rules/acceptance.md` は、ADR ができたら昇格 PR で `- **設計 (ADR)**: …` を足すよう求めている。この AT には張り替える行が無く、ADR へのリンクを足す差分は張り替えではない。ADR-3286 の分類器はこの差分を AT のパスの段階（Medium）に数えるので、規約どおりに AT へリンクを足した昇格 PR は、必ず Medium になって例外から外れる。

ADR-3309 の昇格 PR #3392 では、Medium の理由は AT の 1 行（関連 ADR の並びへのリンクの追加）だけだった。2 つの規則は、それぞれ単独では正しい。

## 決定

**新しい ADR を足す PR では、AT の hunk が「メタデータの ADR の行に、新しい ADR へのリンクを足すだけ」なら、張り替えと同じくその AT を Low に数える。**

1. **判定は許す形を文法で決める**（`isLinkInsert`）: 変えてよいのは、ラベルが `設計 (ADR)` / `関連 ADR`（`関連ADR` / `ADR` も）の行（`- **<ラベル>**: <値>`）だけ。許す変更は 3 つで、値が新しい ADR へのリンクだけの行を足す、空の値をそのリンクで埋める、既存の値の先頭か末尾にリンクを読点・カンマでつなぐ。hunk の削除行は、どれもこの形で変わった行として、順に対応しなければならない。
2. **位置も決める**: 変更後の AT の中で、行は冒頭のメタデータの並び、つまり frontmatter の後のタイトル（`# `）から最初の見出しまでの間にあり、その間にフェンスの行を挟まない。行ごと足す ADR の行は、別のメタデータ項目（`- **<ラベル>**:`）の行の後（その項目の続きの行や子リストの後でもよい。空行・引用・表を挟まない）にあり、すぐ下の行が別の項目・空行・ファイルの終わりのどれかでなければならない。上の項目の続きの行や子リストを引き取らず、メタデータの項目が 1 つ増えるだけになる。判定には変更後の AT の全文を使い、読めなければ当たらない。
3. **AT に限る**: ADR の行は AT の規約が決めた形で、ほかの Markdown（README、roadmap、Design Doc など）では同じ行に決まった意味が無い。AT 以外のファイルは、張り替え以外ではパスの段階のまま。
4. **リンクの形**: リンク先は新しい ADR のパス（相対パスを許し、anchor は付けない）に限り、URL の中に ADR のパスが現れるだけのものは当たらない。リンクの文字列は、**リンク先のその ADR の**ファイル名・パス・`ADR-<n>` に限る（新しい ADR が 2 本あっても、片方の名前でもう片方を指せない）。ファイル名が `<番号>-<英小文字・数字・ハイフン>.md` でない新しい ADR は、リンク先として使わない。ファイル名の `)` や `]` がリンクの外へ文章を運べるからである。
5. **ほかの変更が混ざれば外れる**: ほかのラベルの行、行頭や並びの途中への挿入、コロンの後ろや行末の空白の変化、同じ hunk の手動項目のチェックや文言の変更があれば、そのファイルはパスの段階のままになる。
6. **Design Doc の削除は条件にしない**: 張り替えはリンク元（削除した Design Doc）が要るが、リンクの追加は新しい ADR があれば判定できる。新しい ADR を足す PR であることは張り替えと同じく条件にする。

## 理由

- **AT の規約が正しいほうに動いた結果だから、規約は戻さない。** Design Doc は昇格で削除されることが規約で決まっているので、AT から指すと必ず切れる（ADR-2348、TPL-2254）。分類器を張り替えに合わせて AT に Design Doc を指させると、この判断を覆すことになる。
- **足すだけの差分は、張り替えと同じく判断を含まない。** どちらも昇格に伴うリンクの整合で、変わるのは新しい ADR への導線だけである。ADR-2331 が除外したかった「受け入れ条件そのものの変更」は、同じ hunk に混ざれば判定から外れる。
- **張り替えは場所を問わず、リンクの追加は AT に限る。** 張り替えは「消えるファイルを指していた行を、後継へ向け直す」という、どのファイルでも同じ意味を持つ差分なので、ADR-2331 のとおり場所を問わない。リンクの追加は、AT の規約が決めたメタデータの行という形に頼って安全を保つ。その形が決まっていないファイルに同じ判定を当てると、意味の決まらない行を足せてしまう（実装 PR のレビューで、README や CLAUDE.md に足せることが分かった）。spec や TPL など別の記録がメタデータの行の規約を持てば、その記録を足す。
- **削って比べるのではなく、許す形を決め打ちにする。** 最初の実装は「追加行からリンクを消すと削除行に戻る」かを見て、リンクを消すとラベルだけになる行は無視していた。実装 PR のレビューで、任意の太字ラベルの行（`- **承認済み**: [ADR-12](…)`）を足せること、行頭に置いたリンクと区切りがチェックボックスやコードフェンスや見出しを壊せることが分かった。2 回目のレビューでは、行そのものは正しくても、frontmatter の上・表の見出しと区切りの間・コードフェンスの中に足せることが分かった。3 回目のレビューでは、上の項目の続きの行や子リストの直前に足すと、それを引き取って上の項目の中身を変えられること（実在の AT で再現した）、本文の `- **手順**:` などの後にも足せることが分かった。人間を通らない経路を開く判定なので、AT の規約が書く形と位置だけを通し、それ以外はパスの段階に倒す（TPL-3286）。
- **実例で確かめた。** この分類器で #3392 のブランチを判定すると Low になる（それまでは Medium）。`docs/acceptance/` の AT のうちメタデータの並びを持つ 283 件すべてで、並びの最後の項目の後に ADR の行を足す変更が Low になる。並びを持たない古い形式の 96 件はパスの段階のまま。

### 柵

- `scripts/review/tier.test.ts`「ADR promotion (ADR-2331)」: 関連 ADR の並びへの追加と `- **設計 (ADR)**:` 行の追加だけの AT が、Design Doc の削除の有無にかかわらず Low になること。手動項目のチェックが同じ hunk に混ざると Medium のままになること。`isLinkInsert` の呼び出しを外すと、Low になるテストが落ちる。
- `scripts/review/tier.test.ts`「isLinkInsert」: 値の先頭・末尾への追加、連続した 2 本、新しい行、空の値を埋める形を受け入れること。ほかのラベル・字下げした行・frontmatter の上と中・空行の後・表の中・コードフェンスの中の行・本文の項目の後・子リストや続きの行の前・行頭への挿入（チェックボックス、見出しの前）・値の途中への挿入・anchor 付きのリンク・空白の変化・もう 1 本の新しい ADR の名前で指すリンク・名前でないリンク文字列・URL の中のパス・同じ行や hunk のほかの変更を拒むこと。ファイル名に `)` を含む新しい ADR をリンク先に使わないこと。同じ挿入を README・roadmap・Design Doc に入れてもパスの段階のままであること。

## 却下した案

### AT の規約を戻し、AT に Design Doc を指させる

昇格 PR は張り替えになり、分類器は変えずに済む。ただし Design Doc は昇格で削除されることが決まっているので、昇格までのあいだ AT は必ず切れるアドレスを持つ。ADR-2348 が直した問題を戻すことになる。

### 昇格 PR では `docs/acceptance/**` の変更を Low に数える

判定は単純になる。ただし AT の受け入れ条件そのものの変更（手動項目のチェックなど）まで人のレビューなしに通る。ADR-2331 がこの形を却下した理由がそのまま当てはまる。

### AT へのリンクの追加を、昇格とは別の PR にする

昇格 PR は Low のまま通る。ただしリンクを足す 1 行のために PR とレビューが 1 往復増え、その PR 自身も AT の変更として Medium になる。

## 影響

- AT のメタデータに ADR へのリンクを足す昇格 PR は、ほかに変更が無ければ Low になり、auto-merge の例外に入る。分類器は AT の変更後の全文を読むようになった。
- メタデータの並び（`- **<ラベル>**:` の項目）を持たない古い形式の AT にリンクを足す昇格 PR は、従来どおり Medium になる。
- 既存の張り替えの判定は変わらない（`isLinkSwap` は名前の判定を共有する関数に切り出しただけ）。
- `.claude/rules/adr.md` の適用条件は 5 種になった。`docs/process/review.md` の段階の表も合わせた。
