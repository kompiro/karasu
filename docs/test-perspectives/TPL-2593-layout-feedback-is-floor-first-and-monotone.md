# TPL-2593: レイアウトのフィードバックは floor-first かつ単調

## 観点

karasu のレイアウトは長らく**前向き一方向**だった。層を決め、順序を決め、座標を決め、
配線する。出来上がった図を測って前段に返す経路は無い。その一方向性が、
「同じ入力 → 同じ SVG」「差分は局所的」（`docs/concepts.md` Goals）を無料で保証していた。

測定値を配置に返し始めた瞬間、その保証は無料でなくなる。**フィードバックを足すなら、
決定性を明示的に設計し直す。** 具体的には 3 つが同時に成り立っていること。

1. **候補は入力だけで決まる** — 候補列（試す予算・試す gap）は、モデルと定数だけから
   導出される。viewport の幅、実行環境、前回の結果、乱数は入らない。karasu は CLI で
   headless にレンダリングするので、画面を読む解は静かに壊れる。
2. **既定候補が先頭で、厳密改善のみが勝つ** — 現行の定数を最初の候補に置き、
   目的関数が**厳密に**良いときだけ置き換える。これで「改善が無い入力では出力が
   1 バイトも変わらない」が構造的に保証され、スナップショットの churn と
   レビュー不能な差分が消える（[TPL-2048](TPL-2048-label-placement-measured-and-byte-stable.md)
   の byte-stable 要求と同じ性質を、配置側で満たす形）。
3. **停止が単調性で説明できる** — 「良くなるまで繰り返す」ではなく、
   「この向きに進めると指標は単調だから、ここで打ち切ってよい」と言える形にする。
   収束判定つきのループは、停止しない入力と、回数上限に結果が依存する入力を必ず生む。

## 想定される失敗モード

- **反復修復ループを入れてしまう。** 「衝突があれば動かして再配線、衝突が消えるまで」。
  停止条件が入力依存で、上限を付ければ結果が上限に依存する。要素 1 個の追加で図全体が
  組み替わり、compare / diff モードの差分が読めなくなる。
- **採点する箱が、最終的に出る箱と違う。** 内側の content box で採点し、その外側に付く
  chrome（side column・コンテナ余白・フレーム題字）を勘定に入れない。指標は改善するのに
  出力は悪化する。#2593 では content box で採点した結果、root view の比率が 1.16 → 2.28 に
  悪化した。**採点は最終出力の寸法で行う。**
- **候補ごとの試行が純粋でない。** 破棄したはずの回が Map / 配列を書き換えており、
  勝った回の結果に混ざる。全要素ちょうど一度配置する不変（[TPL-1738](TPL-1738-relayout-into-group-preserves-placement-and-edges.md)）が
  試行の間に崩れる。
- **退化入力で候補が 1 つも残らない。** 空のビューは 0 × 0 になり、比率も面積も定義できない。
  フォールバックが無いと `null` が呼び出し元に出る（#2593 の実装で実際に踏んだ）。
- **フィードバックが片方の経路にしか入らない。** single / multi / drill-down / deploy の
  どれかが素通りし、同じモデルがビューによって別の規則で並ぶ（[TPL-219](TPL-219-parallel-function-parity.md)）。

## チェックリスト

配置に測定値を返す経路を足すときに確認する:

- [ ] 候補列を生成する関数が **モデルと定数だけを引数に取る**。viewport / 時刻 / 乱数 /
      前回結果を読んでいないことを、シグネチャで確認できる。
- [ ] **同じ入力で 2 回走らせて座標が完全一致する**テストがある。
- [ ] **現行定数が候補の先頭**で、**厳密比較**（`<` であって `<=` ではない）で置き換わる。
      「今のままで十分な入力では座標が完全一致する」テストがある。
- [ ] 採点している寸法が、**呼び出し元が最終的に使う寸法**と同じ。内側の box で
      採点していない。
- [ ] 試行が**純粋**である（破棄した回の副作用が残らない）。共有 Map を書き換える実装なら、
      試行ごとに作り直しているか確認する。
- [ ] **打ち切り条件が単調性で説明できる**。「もう良くならない」ではなく「この向きでは
      指標が単調なので、ここから先は必ず悪い」と言える。
- [ ] **退化入力**（要素ゼロ / 1 要素 / 全要素同一サイズ）で結果が返る。
- [ ] 並列に存在する全レイアウト経路が同じ規則を通る（TPL-219）。

## 既知の対処パターン

#2593 で採った形:

| 何を | どう解いたか |
| --- | --- |
| 候補列 | 下限（現行定数）から幾何級数で N 段。整数に丸めて重複除去 |
| 目的 | 帯（縦 16:9〜横 16:9）の内側でキャンバス面積が最小。同点は小さい予算を残す |
| 既定の保存 | 下限を先頭に置き、厳密に小さい面積のときだけ置換 |
| 停止 | 予算を広げると幅は減らず高さは増えないので、帯の上端を超えたら打ち切り |
| 純粋性 | 配置関数は入力から新しい Map を作って返す。測定はメモ化して再計算のみ共有 |
| 退化 | 帯に入る候補が無ければ最も正方形に近い回、それも無ければ最初の回を返す |
