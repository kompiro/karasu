# TPL-3027: 複数の要素を 1 つの見た目に重ねるのは、それらが見た目と意味で区別できないときだけにする

## 観点

密な図を読みやすくするために、複数の要素を 1 本の線や 1 つの図形に重ねることがある。
重ねた後に読み手が見るのは、いちばん上に描かれた 1 つだけになる。下の要素が上の要素と
違う見た目（色・太さ・破線）や違う意味（sync と async、diff state）を持っていれば、
その違いは canvas から消える。

したがって、重ねるかどうかは「重ねたら読み手の失うものが無いか」で決める。判定は 1 つで、
**重ねる要素どうしが、描画結果を変えるすべての次元で一致するか**。1 つでも違えば重ねずに、
変換前の描画に戻す。

`docs/concepts.ja.md` は sync と async の区別を「視覚的装飾ではなく構造の意味論」とし、
ADR-2958 は種別の違う edge を同じ束に入れない。この観点はそれを、重ねる変換一般に広げる。

## 想定される失敗モード

- `A -> B` と `B --> A` を 1 本に重ねた結果、上に描かれた実線だけが見え、非同期の依存が canvas から消える
- 色の違う 2 本（`edge[to=X]` で色分けした hub の edge など）を重ねて、片方の色が見えなくなる
- diff 表示で、片方だけ `added` の組を重ね、追加が見えなくなる
- 判定の鍵を `(from, to)` のように一部の属性だけで作り、style や diff state の違う組まで重ねる（TPL-1352 と同じ形）
- 重ねない場合の描画を用意せず、条件から外れた組が描かれなくなる

## チェックリスト

要素を重ねて描く変換を足す・変えるとき:

- [ ] 描画結果を変える次元（種別・解決済みの style・diff state・ghost かどうか・束への所属）を列挙し、すべてを重ねる条件に入れた
- [ ] 条件から外れたときは、変換前と同じ描画に戻る
- [ ] 次元を 1 つずつ違えた組を用意し、それぞれ重ならないことをテストした
- [ ] 重ねた後も、各要素の identity（id・`<g>`・hit-line）と全文への経路が残る（TPL-3022、TPL-1886）

## 既知の対処パターン

- ADR-2958: 種別の違う edge は同じ gutter lane の束に入れない。束の中でも edge は 1 本ずつ `<g>` を持つ
- 重ねても `<g>` を要素ごとに残し、同じ座標を共有させるだけにする。重ねる条件から外れたら、共有させないだけで今日の描画に戻る
- 対象外: ADR-1185 の並列 edge の束は、重ねるのではなく同じ `(from, to)` の線を離して描くので、この観点の対象ではない
