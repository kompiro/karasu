# TPL-3027: 複数の要素を 1 つの見た目にまとめるのは、それらが見た目と意味で区別できないときだけにする

## 観点

密な図を読みやすくするために、複数の要素を 1 本の線や 1 つの図形にまとめることがある。
まとめた後に読み手が見るのは 1 つの見た目だけになる。まとめた要素どうしが違う見た目（色・太さ・
破線）や違う意味（sync と async、diff state）を持っていれば、その違いは canvas から消えるか、
どちらの要素のものか分からなくなる。

したがって、まとめるかどうかは「まとめたら読み手の失うものが無いか」で決める。判定は 1 つで、
**まとめる要素どうしが、描画結果を変えるすべての次元で一致するか**。1 つでも違えばまとめずに、
変換前の描画に戻す。

`docs/concepts.ja.md` は sync と async の区別を「視覚的装飾ではなく構造の意味論」とし、
ADR-2958 は種別の違う edge を同じ束に入れない。この観点はそれを、まとめる変換一般に広げる。

## 想定される失敗モード

- `A -> B` と `B --> A` を 1 本に重ねた結果、上に描かれた実線だけが見え、非同期の依存が canvas から消える
- 色の違う 2 本（`edge[to=X]` で色分けした hub の edge など）を重ねて、片方の色が見えなくなる
- diff 表示で、片方だけ `added` の組を重ね、追加が見えなくなる
- 判定の鍵を `(from, to)` のように一部の属性だけで作り、style や diff state の違う組まで重ねる（TPL-1352 と同じ形）
- まとめない場合の描画を用意せず、条件から外れた組が描かれなくなる

## チェックリスト

要素をまとめて描く変換を足す・変えるとき:

- [ ] 描画結果を変える次元を列挙し、すべてをまとめる条件に入れた。解決済みの style（種別・色・太さ・線種）と diff state だけでなく、style の解決の後に決まる見た目（layout が立てる印、たとえば ghost・cyclic・Group-by の逆向き破線、束への所属）も数える
- [ ] まとめること自体が見た目を変えないか確かめた。同じ線に 2 本を重ねると、破線の位相のずれ、半透明の線の重なり、全長に掛かる casing や hop の隙間が、どちらの要素のものか分からなくなる。重ねずに分けて描ける（線の半分ずつ、など）ならそちらを選ぶ
- [ ] 条件から外れたときは、変換前と同じ描画に戻る
- [ ] 次元を 1 つずつ違えた組を用意し、それぞれ 1 つにまとまらないことをテストした
- [ ] まとめた後も、各要素の identity（id・`<g>`・hit-line）と全文への経路が残る（TPL-3022、TPL-1886）

## 既知の対処パターン

- ADR-2958: 種別の違う edge は同じ gutter lane の束に入れない。束の中でも edge は 1 本ずつ `<g>` を持つ
- まとめても `<g>` を要素ごとに残し、座標を共有させるだけにする。条件から外れたら、共有させないだけで今日の描画に戻る
- #3027: 両方向の組は 2 本を重ねず、各 edge が共有の線の自分の target 側の半分だけを描く。edge ごとの装飾がその半分にだけ掛かる
- 対象外: ADR-1185 の並列 edge の束は、重ねるのではなく同じ `(from, to)` の線を離して描くので、この観点の対象ではない
