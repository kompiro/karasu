# TPL-2385: 接続点は描かれた輪郭に付く

## 観点

**bounding box は図形ではない。** レイアウトが確保した矩形と、実際に描かれる輪郭が
一致するのは長方形だけで、カード・楕円・多角形・外部アイコンでは box の内側に空白が
残る。エッジ端点・バッジ・ボタンといった「ノードの外形を基準に置くもの」を box に
付けると、その空白のぶんだけ図形から浮く。**外形を基準に置くものはすべて、図形が
宣言した輪郭を基準に置く。**

TPL-2179 の裏返しの関係にある。あちらは「box より**外へ**広げた図形は実被覆で測る」、
こちらは「box より**内側に**描かれる図形は宣言した輪郭で測る」。共通する原則は
1 つで、**描画と幾何判定の基準は同じものでなければならない**。

### 検証は描画出力で測る

輪郭と接続点はどちらも同じ box から導かれるので、**両方が一緒にずれてもテストは
緑のままになる**。#2385 はその形で起きた: エッジは box の端に、図形は box の 70% 幅に
置かれ、どちらのコードも「box を基準にしている」点では一貫していた。したがって
**幾何のテストは、実際に emit された描画物（SVG の `rect` / `circle` / `path`）から
輪郭を読み、それに対して端点を assert する**。box から再導出した期待値で測ると、
検証しているのは「2 つの式が同じ box を使っているか」であって「図と線が合っているか」
ではない。

## 想定される失敗モード

- エッジ端点が box の辺に置かれ、**図形の外側の空白から線が始まる**。図形が box より
  30% 狭い場合、辺の中央付近に集まる上下の端点は輪郭に載るので、**横に接続先が来た
  ときだけ露見する**（#2385 は側面アンカーで初めて発覚した）。
- バッジ・ボタンを box の角に置き、**カード外へ浮いて入ってくるエッジや隣のカードと
  重なる**（ADR-2366 P5）。描画順で見え方が変わり、静的出力にも残る。
- 新しい図形を registry に足したとき、描画関数だけ書いて輪郭宣言（`portFrame` /
  `contentInset`）を書き忘れる。**既定値が bounding box なので何も壊れず**、その
  図形だけ静かに古い挙動へ戻る。
- ルーティングの再経路化パスが端点を自前で置き直し、**配分時に適用した輪郭が
  上書きされる**（ADR-2366「実装で設計を覆した点」— 座り直しパスが要る）。
- テストが box から期待値を再計算しており、図形と接続点が一緒にずれても検出しない。

## チェックリスト

図形を追加・変更する、または外形基準の要素を置くときに確認する:

- [ ] 図形が **輪郭の在処を宣言している**（`portFrame(w, h)` の spans / depth、および
      テキスト側の `contentInset`）。宣言のない図形は bounding box が輪郭であること
      が正しい場合（`box`）に限る。
- [ ] 端点・バッジ・ボタンを置くコードが、**box ではなく宣言された輪郭 / インセット**
      を読んでいる。box を読む経路が残っていないか grep で確かめる。
- [ ] **描画出力から輪郭を読むテスト**がある（SVG の図形要素をパースし、端点がその
      境界に載ることを assert する）。box から期待値を再導出していない。
- [ ] そのテストが **図形を狭めると落ちる**ことを一度確認した（描画関数を一時的に
      内側へ寄せて赤くなることを見る）。落ちないなら box を測っている。
- [ ] **接続先が横にあるケース**が含まれている。上下の端点は中央に寄るため輪郭に
      載ってしまい、側面アンカーがないと不一致が隠れる。

## 既知の対処パターン

ADR-2366（#2412 / #2420 / #2422）で採った形:

| 何を | どう解いたか |
| --- | --- |
| 接続点 | シェイプが辺ごとに `portFrame(w, h)` で spans（輪郭が覆う区間）と depth（食い込み）を宣言し、ポートはそこに座る。ルーティング後に座り直しパスを 1 回通す |
| テキスト | `contentInset` が per-side の内側余白を返し、測定と描画の双方が同じ値を読む |
| バッジ・ボタン | box の角に浮かせず、カード内側の右詰めレーン（corner lane）の住人にする。レーンは輪郭インセットを基準に置く |
| クロームとの競合 | 輪郭は事実なので端点は寄せる、keep-out は選好なので曲がりが吸収できるときだけ寄せる |

図形の輪郭が式で書けない場合（cloud のような波打つ輪郭）は、**描画カーブを平坦化して
光線ごとに交差させる**。宣言した span の外では depth が意味を持たない点にも注意する。
