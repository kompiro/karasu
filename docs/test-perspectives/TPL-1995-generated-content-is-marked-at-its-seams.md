# TPL-1995: 生成物の不確かさは、不確かな場所に印を付け、解決した人が消せる形にする

## 観点

推論で作った成果物を人に見せるとき、**どこが推測でどこが読み取りかを成果物自身が言えない**と、読み手は全体を同じ確度で受け取る。しかも生成物は往々にして自信ありげな文体で出てくるので、確度の差は文面からは読み取れない。

対処は 3 つの性質をまとめて満たす必要がある。1 つでも欠けると印は機能しない。

1. **粒度が不確かさの粒度と一致していること。** 文書全体に 1 つのスコアを付けると、確信している 9 割と怪しい 1 割が平均されて、どちらの情報も失われる。実測（[#1991](https://github.com/kompiro/karasu/issues/1991)）では生成の誤りは全体に散らばらず、**人間でも判断が割れる継ぎ目に集中**していた。印を置くべきはその継ぎ目である。
2. **人が消せること。** 印は「レビューが済んだ」を表現する手段でもある。消すのに構造の変更が要る形（別ファイル・別セクション・ID の付け替え）にすると、レビューしても印が残り、残った印は次の読み手に嘘をつく。**1 トークン消せば済む形**にする。
3. **印がゲートでないこと。** 低確度を理由に描画を拒む・警告を出す・順位を下げると、生成側は印を付けないほうが得になる。正直さに罰を与える設計は、正直さを消す。

3 つ目が特に落としやすい。「低確度なら警告」は一見安全側だが、**印を付けたら怒られる**なら次の生成では付かなくなる。

## 想定される失敗モード

- **文書レベルの単一スコア**（`confidence: 0.82` をヘッダに 1 つ）。読み手はどこを疑えばいいのか分からず、結局全部を疑うか全部を信じるかになる
- **印が消せない / 消し忘れる**。レビュー済みの部分に印が残り続け、`✅` 列と同じ drift を起こす（[TPL-1032](TPL-1032-derived-state-staleness.md)）。逆に、消すことが「レビューした」の記録になっていれば drift しない
- **印にペナルティを付ける**。低確度ノードを警告・非表示・降格にすると、生成側が印を省く動機になる。**正直さは無罰でなければ続かない**
- **語彙が閉じすぎている**。`low` / `medium` / `high` 以外を弾くと、人が書きたい「ここは議論が割れた」という注記の行き場が消え、コメント（機械が読めない場所）に逃げる。既定値を持たない opaque 受理にする
- **印の既定描画が無い**。名前だけ受理して見た目が変わらないと、書いた人は効いているか分からない（[TPL-1503](TPL-1503-accepted-vocabulary-must-have-effect.md) の「受理・無効果」）
- **印が無い = 確認済み、と読める設計**。生成物全体が未確認なのに一部にしか印が無いと、印の無い部分が「確認済み」に見える。既定の解釈をどちらに置いたかを明記する

## チェックリスト

生成物に確信度・出所の印を導入する、または生成パイプラインの出力形式を変えるとき:

- [ ] 印の粒度は、**実際に誤りが集中する単位**に合わせたか（文書全体ではなく、判断の分かれる要素ごと）
- [ ] 印を消すのに構造変更が要らないか。消す操作が「レビュー済み」の記録として成立するか
- [ ] 印があることによる**不利益がゼロ**か（描画拒否・警告・降格をしていないか）。不利益があるなら、生成側が印を省く経路を塞いだか
- [ ] 既知の水準の**外側の値を受理**するか。受理するなら display-only として保持し、エラーにしていないか
- [ ] 印に**既定の描画効果**が同じ PR で入っているか（TPL-1503）
- [ ] 「印が無い」の意味を spec に明記したか（未確認が既定か、確認済みが既定か）
- [ ] 生成側が印を**実際に付ける**ことをテストしているか。語彙だけ足して生成側が使わないのが一番ありがちな不発

## 既知の対処パターン

- **要素ごとの annotation + 省略可能な水準**: karasu の `@draft` / `@draft(confidence: "low")`。裸の `@draft` で完結し、水準は refinement。消すのは 1 トークン
- **未知の値は opaque で受理**: `until`（[ADR-1568](../adr/1568-migration-intent-annotation-params.md)）と同じ degradation。機械可読な 3 水準の外は display-only にして、人の注記を追い出さない
- **印に罰を与えない**: 既定描画は badge だけ。診断も filter の既定除外も付けない。読み手が自分で filter するのは自由だが、ツールが先回りしない
- **消すことをラチェットの単位にする**: 人が `@draft` を消した PR がそのままレビュー済みの記録になる（karasu-nest の PR 還元 — [#2289](https://github.com/kompiro/karasu/issues/2289) / [#2228](https://github.com/kompiro/karasu/issues/2228)）
