# TPL-3494: エッジは自分の端点のカードの内側も通らない。障害物の検査は端点を除外するので、別に測る

## 観点

ルーティングの障害物検査（`ObstacleIndex.forEdge`、[TPL-1927](TPL-1927-routing-measures-crossings-and-penetrations.md) の貫通 0）は、エッジ自身の 2 枚の端点カードを障害物から外す。端点はカードの縁にあり、線は必ずそこに触れるからである。

この除外のため、**線が自分の端点カードの内側を通っても、どの検査にも引っかからない**。直線は clear と判定されてそのまま残り、カードがエッジより後に描かれるので、終点側を通る区間と矢印はカードに隠れる。

したがって端点の辺を決めるロジックを変えるときは、障害物の貫通とは別に、**各エッジの線が自分の端点カードの内側を通らないこと**を測る。

## 想定される失敗モード

- **配置の単位を描画上の位置と取り違える**（#3494）: 初期アンカーは「同じ layer なら横並び」として左右の辺を使っていた。幅の上限で 1 つの layer が複数の行に折り返すと、同じ layer の 2 枚が別の行にあり、右辺から左辺への直線が両方のカードを突っ切る。Umami の `UmamiApp` で 41 本中 12 か所、矢印が隠れたのは 6 本。#3027 で両方向の組を 1 本にすると、両端の矢印が隠れて向きの無い線に見えた。
- **柵が green のまま見逃す**: 貫通 0 の柵は端点を除外する定義どおりに動いていて、メトリクスは正しい。端点の内側は測る対象に入っていなかった。

## チェックリスト

端点の辺や位置を決める・動かす変更で確認する:

- [ ] 各エッジの線と、その 2 枚の端点カードの内側の交差を数え、0 であることを確かめた（矩形のカードで測る。円筒などの外形は縁が bbox の内側にあり、bbox で測ると外形どおりの端点まで数えてしまう）
- [ ] 終点の矢印（終点から少し戻った点）が終点カードの外にあることを確かめた
- [ ] 辺を選ぶ条件が、layer や tier の番号ではなく、描画上の位置（縦に重なるか、どちらが上か）で決まっていることを確かめた
- [ ] 足したテストが修正前のツリーで落ちることを確認した

## 関連テスト

- `packages/core/src/renderer/layout-edges.test.ts` — `anchors between cards of one layer on different rows (#3494, TPL-3494)`: Umami の `UmamiApp` で、自分の端点カードの内側を通るエッジが無いこと、矢印が終点カードの外にあること、同じ行のカードは左右の辺のままであること。修正前のツリーで前の 2 件が落ちる
