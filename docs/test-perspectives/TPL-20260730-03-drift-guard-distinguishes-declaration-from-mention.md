# TPL-20260730-03: drift guard は「宣言」と「言及」を区別する — 前方参照を stale と誤検出しない

## 観点

ドキュメントと実装定数の drift を縛るテストは、ドキュメント中のトークンを 2 種類に区別しなければならない。

- **宣言** — そのドキュメント自身が「今の値」として名乗るもの。実装定数と一致すべき対象
- **言及** — 散文が別の値に言及するもの。過去版との比較、次期版への予約、廃止済み記法の説明など

「正典の値以外が 1 つでも現れたら fail」と書くと両者を同一視することになり、**正当な言及がテストを落とす**。特に「現行版は freeze、次期版は設計中」の期間は前方参照が増え続けるため、guard が新しい設計作業そのものをブロックする。

判定は「値が異なるか」ではなく **「その言及が意味的に古いか」** で書く。バージョンなら順序比較（現行より前 = stale、以降 = 前方参照として合法）、キーワードなら「廃止済みリストに載っているか」といった形になる。

## 想定される失敗モード

- 単独では green な 2 つの PR が、マージすると red になる（片方が前方参照を追加し、もう片方が guard を追加する）。どちらのレビューでも気付けず、main が壊れる
- guard を追加した PR は「まだ前方参照が無い」状態で書かれるため、書いた時点では正しく見える
- 回避のためにドキュメント側の正当な記述を削る／guard を無効化する、という誤った修正に流れる
- 「◯◯ 以外は書いてはいけない」という guard が、仕様の説明能力（次期版の予約、非推奨の説明）を silently 制限する

## チェックリスト

drift guard を書く / 変更するときに確認する:

- [ ] guard が拾うトークンのうち、**正典が名乗る 1 箇所**と**散文が言及する箇所**を区別できているか
- [ ] 「値が違う」ではなく「意味的に古い」で fail 条件を書いているか（バージョンなら順序比較、語彙なら廃止リスト照合）
- [ ] 前方参照（次期版・未実装機能への予約）を書いたドキュメントで guard が green のままか、合成入力のテストで固定しているか
- [ ] 順序比較を文字列比較で代用していないか（`"1.10" < "1.9"` は文字列では真）
- [ ] guard 追加 PR と、その guard が縛る対象を編集する別 PR が並行していないか（並行時は semantic merge conflict になる）

## 既知の対処パターン

- **順序比較で stale だけを弾く** — `packages/core/src/language-version.test.ts` の `staleVersions(doc, current)`。`.krs language v<x.y>` を全件抽出し、`current` より前のものだけを返す。v1.0 が現行、syntax.md の「promotion は `.krs language v2.0` に登録」は合法として通る
- **合成入力で意味論を固定する** — 実ドキュメントの走査だけだと「今たまたま green」なのか「意味論が正しい」のか区別できない。stale / 前方参照 / 現行値 / 桁違い（1.10 vs 1.9）の 4 ケースを合成文字列で assert する
- **片方向に絞る**（[TPL-20260511-02](TPL-20260511-02-spec-doc-reference-data-sync.md)）— 「正典 → 再掲」の subset だけを縛り、逆向きを縛らない。本観点は同じ「guard を過剰に強くしない」系の判断
