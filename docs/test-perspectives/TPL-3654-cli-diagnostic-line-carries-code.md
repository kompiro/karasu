# TPL-3654: CLI が診断を出す行は locale によらないコードを持ち、手順書はそのコードで判定する

## 観点

診断コードは安定 API（ADR-1567）だが、利用者に届くのは出力された行だけである。コードが行に載っていなければ、消費者は翻訳された文章を照合するしかなく、locale や文言の変更で黙って壊れる。

守る不変条件は 2 つある。

- カタログの診断を流す CLI の箇所は、同じ形でコードを行に載せる（`karasu fmt` の `Cannot format: ... (<codes>)` は文中に書く別の形として残す）。1 か所でも漏れると、その出力だけ照合が空振りする。
- 手順書が判定に使うコードは実在し、出力の形と一致している。

照合が空振りしたときに「該当なし」と区別できないのが、この観点の核心である。grep の結果が空なら、モデルが正しいようにも見える。

## 想定される失敗モード

- **存在しない形を照合する**: #3640 で見つかった。`reverse-architecture` skill はコードを grep していたが、CLI はコードを出さないので結果は常に空で、壊れたモデルでも停止条件を通っていた。
- **翻訳された文章を照合する**: メッセージの断片での照合は、日本語の locale で空振りし、`LC_ALL=C` で固定しても文言の変更で空振りする。
- **出力の箇所が増えてコードが漏れる**: `render` は載せたが、新しいコマンドや `diff` のように自前で行を組む箇所が載せない。
- **1 行にならない行**: 利用者の文字列やパスは `\n`、`\r`、U+2028 を含みうる。行末にコードを置く形では 1 行目だけを読む消費者がコードを取りこぼし、続きの行が `Warning: ...` で始まれば別の診断に見える。
- **出力の形を変えて古い手順書を壊す**: 手順書は CLI と別に配布され、Step 0 は版の下限しか見ない。接頭辞を変えると、古い手順書の照合が黙って空になる。

## チェックリスト

CLI の診断の出力、またはそれを読む手順書を変えるときに確認する:

- [ ] カタログの診断を流す箇所が、形を組む共通の関数を通っているか。
- [ ] 手順書の判定が翻訳された文章を照合せず、locale を `ja` にしても同じ結果を返すか。 [judgment]
- [ ] 行の区切りを含むメッセージやパスでも、全体が 1 行で、コードが同じ行に載っているか。
- [ ] 手順書が `` `[code]` `` の形で書いたコードが、`DiagnosticParamsByCode` / `WarningKind` に実在するか。
- [ ] 手順書が判定に使うコードを、裸の語ではなく `` `[code]` `` の形で書いているか。 [judgment]
- [ ] 出力の形を変えるとき、すでに配布された手順書の照合が動き続けるか。動かないなら、空振りせず止まる形になっているか。 [judgment]

## 既知の対処パターン

- 行の形を 1 か所の関数に集める（[TPL-1417](TPL-1417-single-renderer-for-structured-messages.md)）。
- 既存の接頭辞を保ったまま行末に足すと、接頭辞で読む消費者の照合は動き続ける。行全体の完全一致や行末を固定した照合は壊れるので、配布した手順書にその読み方が無いことを確かめ、CHANGELOG で知らせる。
- 手順書には「照合が空なら正しい」と書かず、出力の行をすべて読ませる。

## 関連テスト

- `packages/cli/src/check.test.ts`: 診断の行の接頭辞と位置を確かめる。行末のコードはまだ確かめない。
