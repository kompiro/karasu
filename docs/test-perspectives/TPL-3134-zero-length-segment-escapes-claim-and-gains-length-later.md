# TPL-3134: 長さ 0 の区間を経路に残すなら、後のパスがそれに長さを与えないことを確かめる。与えるなら経路から外す

## 観点

> 起源は出荷済みの bug（retrospective）。#3026 の計測中に Umami の `UmamiApp` で見つかった。examples と `routing-parity.test.ts` の corpus には届く入力が無く、柵は 0 のまま緑だった（TPL-2598）。

経路は「端の stub → 中継の縦線 → 端の stub」のように部品をつないで組む。部品の位置が条件によって重なると、間の区間は**長さ 0** になる。描けば見えないので、無害に見える。

ところが長さ 0 の区間は、区間を相手にする判定から 2 通りに漏れる。

- **長さで選ぶ判定は読み飛ばす。** 列の claim は長さのある縦線だけを登録するので、同じ x を別のエッジが選んでも衝突にならない。
- **向きで区切る判定は区切りとして数える。** チャネルの run は「両隣が縦の水平区間」なので、長さ 0 の縦線の所で 1 本の run が 2 本に分かれる。

後のパスが分かれた 2 本を別々に動かすと（2 本は接しているので別のレーンになる）、長さ 0 だった区間がレーン間隔の長さを持つ。claim をすり抜けた他のエッジも同じことをしていれば、2 本の縦線が同じ x で重なる。判定したときには長さが無く、描くときには長さがある。この食い違いが失敗の原因になる。

したがって、経路を組む段で**長さ 0 になる区間を経路に入れない**のを原則にする。残すなら、後のどのパスも、その区間を区切りにして端点を別々に動かさないことを確かめる。

## 想定される失敗モード

- **双方向の組が 1 本の縦線を共有する。** 隣り合う行の 2 枚を結ぶ双方向のエッジが、両端とも同じチャネルに降りる。corridor の縦線は長さ 0 で claim されず、2 本とも同じ x を選び、レーン分けの後で重なる（#3134、Umami で 2 組）。
- **1 本のエッジがチャネルの中で段差を描く。** 重ならない場合でも、1 本の run で済むエッジが 2 本のレーンを使い、意味の無い段差を描く。行間の予約もそのぶん増える（Umami `UmamiApp` で面積 5.6%）。
- **経路が行って戻る。** 中継点が両端の外にあると、長さ 0 の縦線の手前で経路が同じ線の上を往復する。mixed route ではガターまで出て戻っていた。
- **後段で辻褄を合わせて取りこぼす。** レーン分けの側で長さ 0 の区間をまたいで run をつなぐと重なりは消えるが、点は経路に残り、レーン順・交差マーク・ラベル配置などほかの後段のパスが引き続き見る。

## チェックリスト

経路の部品をつなぐ実装、または区間を長さ・向きで選ぶ判定を変更するときに確認する:

- [ ] 経路の中継点どうしの区間が長さ 0 になる条件を列挙したか（両端が同じチャネル・同じ高さに降りる、など）
- [ ] その条件で、経路を組む段が長さ 0 の区間を入れずに済ませているか
- [ ] 「同じ場所にある」を座標の一致ではなく構造（同じ行間チャネル）で判定しているか。両端の座標を別々の式で求めると、同じチャネルでも値がずれ、長さ 0 ではなく短い区間が残る
- [ ] 残す場合、claim・重なりの検出が長さ 0 の区間を読み飛ばしても困らないか、run の切り出しがそこで区切らないかを確認したか
- [ ] 部品を外した経路が、元の経路の線分の部分集合になっているか（障害物の判定を取り直さずに済むか）
- [ ] 柵の入力に、その条件に届く図があるか。配置が届かせないなら、カードを手で置いた入力で配線のチェーン全体を通したか

## 既知の対処パターン

- **経路を組む段で長さ 0 の部品を外す。** corridor と mixed route は両端の stub をつなぐ関数を共有し、両端がチャネル stub で同じチャネルに降りるときは中継の 2 点を入れず、チャネルの中で 1 本の run につなぐ（`joinEnds` / `joinInChannel`、#3134）。同じ行の U 字（#3026）も同じ関数でつなぐ。2 本の stub が同じ x に降りるときは折れ点を 1 つにして、長さ 0 の水平区間も作らない。
- **同じチャネルかどうかは行間の帯で判定する。** `channelBelow` は上のカード自身の下端から、`channelAbove` は上の行で最も低い下端から測るので、上のカードが行の中で背が低いと、同じチャネルでも両端の `cy` が一致しない。両端が同じ帯の中にあれば同じチャネルとみなし、帯の中央でつなぐ（`sharedChannelY`）。
- **部品を外した経路を、後段の選択が受け入れられるようにする。** ガターを使わなくなった mixed route は corridor を持たないので、ガターの選択（`cheapestSide`）は混み具合 0 として比べ、ガターの占有には積まない。
