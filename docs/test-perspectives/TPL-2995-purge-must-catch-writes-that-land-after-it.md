# TPL-2995: 結果整合のストアで削除を約束したら、削除の後に届く書き込みも消えることを確かめる

## 観点

削除の経路が鍵空間を漏れなく掃除しても（[TPL-2226](TPL-2226-every-key-prefix-must-be-purgeable.md)）、**掃除が終わった後に書かれた鍵**は残る。削除の対象を「まだある」と読んだ要求が、掃除の後で書き込むからである。

compare-and-set の無いストアでは、書いた後に読み直しても閉じない。結果整合のストアは削除の後もしばらく古い値を返すので、読み直しは「まだある」と答え、書いた鍵はそのまま残る。マーカーを書きの前後で確かめる形も、マーカーそのものが別の場所に届くまで見えないので、窓を狭めるだけで閉じない。

「削除から一定時間おいてもう一度掃除する」形も、時刻に頼るかぎり閉じない。待ち時間が足りる根拠は「古い値を読んだ要求は一定時間内に書き終わる」という前提だが、Cloudflare Workers は I/O の待ちに経過時間の上限を設けず、KV の操作にも決まった時間の上限が無い。閉じるのは、消すかどうかを**時刻ではなく状態**（元のレコードがあるか）で決め、書き込みが届いた後に必ず一度は走る回収である。

TPL-2226 が「削除の射程」を見るのに対し、こちらは「削除の時刻」を見る。射程が正しくても、削除が 1 回きりなら、その後に届く書き込みには射程が及ばない。

この失敗はテストで見えにくい。テスト用のインメモリのストアは書いた直後に読めるので、読み直しの防御が常に効いて見える。期限（TTL）を付けた鍵は「いずれ消える」ので、レビューでも約束を満たしたように読める。

## 想定される失敗モード

- 派生データ（画像・サムネイル・キャッシュ）を「初めて求められたときに作って保存」する経路が、アカウント削除の直後に古いレコードを読んで保存し、掃除から漏れる
- 保存の直後にレコードを読み直して防いだつもりでいるが、読み直しも古い値を返す
- 期限で消えることを、削除の約束を満たす手段として扱う（「30 日で消える」は「アカウント削除で消える」ではない）
- 削除から一定時間後にもう一度掃除し、それで閉じたことにする。要求がその時間より長引けば、2 回目の掃除の後に書き込みが届く
- 再掃除のためのマーカーに期限を付け、定期実行が期限より長く止まると、再掃除の機会ごと失う
- テスト用のストアが常に最新の値を返すので、読み直しの防御が効かない順序をテストが 1 度も通らない

## チェックリスト

削除を約束したストアに「読んでから書く」経路を足すとき:

- [ ] その経路が削除の後に書きうるかを、ストアの一貫性の保証（書いた場所以外で古い値が見える時間）から確かめたか
- [ ] 書きうるなら、**削除の後に届いた書き込みを消す仕組み**（元のレコードの有無で判定する定期回収、強い一貫性を持つ持ち主など）があるか。読み直しやマーカーの確認だけで閉じたことにしていないか
- [ ] その仕組みが、要求の長さや伝播の時間に上限を仮定していないか。仮定しているなら、その上限を実行環境が保証しているかを確かめたか
- [ ] その順序（削除が終わる → 古い値を読んだ要求が書く → 読み直しも古い値を返す）を、テスト用のストアに古い値を返させて再現したか
- [ ] 期限（TTL）は最後の受け皿として書き、約束を満たす手段として書いていないか
- [ ] 回収に猶予（作ったばかりのものを消さないための待ち）を入れるなら、その猶予が外れたときに消し過ぎる側にしか効かないことを確かめたか

## 既知の対処パターン

- **元のレコードの無い派生データを定期的に回収する**: 定期実行が派生データの鍵空間と元のレコードの鍵空間を列挙して突き合わせ、元の無いものを消す。判定が状態なので、書き込みがいつ届いても届いた後の最初の回収で消え、失って困る記録も残さない。作ったばかりのものを列挙の遅れで消さないよう、書いてから短い猶予を置く（外れても描き直されるだけ）。nest の OGP 画像の設計（`docs/design/gallery-ogp-preview-image.md`、#2995）
- **書いた直後に読み直す／書きの前後でマーカーを確かめる**: 同じ場所の要求との競合を閉じる。単独では別の場所の要求を閉じないので、定期回収と組み合わせる。`packages/nest/src/store/sessions.ts` の `refreshIfStale`
- **閉じていない競合を明記する**: すぐに閉じられないなら、その経路のコードに「閉じていない」と書いておく。`packages/nest/src/store/submissions.ts` の `update`
