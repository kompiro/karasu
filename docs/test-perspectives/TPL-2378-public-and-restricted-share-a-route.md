# TPL-2378: 公開してよい資源と見せてはいけない資源が同じルートを通るなら、安全側を既定にし、反転は 1 か所の判定に閉じる

## 観点

「public repository のモデルは公開する。private repository のモデルは配信しない」のように、**同じ URL 形（`/<owner>/<repo>`）が、資源によって公開と非公開に分岐する**設計がある。分岐そのものは正しくても、実装は 1 か所では終わらない。1 つの応答は本文のほかに、キャッシュ規約・CORS・`ETag`・OGP メタデータ・アクセスログ・検索エンジンへの露出という**副次チャネル**を持ち、そのどれもが「見せてよいか」に従わなければならない。

失敗は本文で起きない。**本文は正しく 404 を返しているのに、副次チャネルの 1 つだけが緩和されたままになる**ことで起きる。しかもこの種の緩和は「public を速くしたい」という正当な要求から入るので、レビューでは機能追加に見える。

したがって観点は 2 段構えになる:

1. **既定は安全側**である。新しい応答経路・新しいヘッダ・新しい派生物は、何も書かなければ「配信しない・キャッシュしない・共有しない」側に落ちる。緩和は明示的な操作でしかできない。
2. **反転の判定は 1 か所**にある。「この資源は誰に見せてよいか」を答える関数が 1 つあり、キャッシュも CORS も HTML 面もその答えを**参照する**。判定条件（`visibility === "public"` 等）を各所で書き直さない。

2 が要るのは、条件が散ると**片方だけ更新されるから**である。判定の意味が後から変わったとき（「public だが opt-out されている」が増えたとき）、更新漏れは型検査にも機能テストにも映らない。

## 想定される失敗モード

- `Cache-Control: no-store` を既定にしてあるサービスで、public 生成物だけ `public, max-age=...` に緩めた。緩和条件が判定関数ではなくルートハンドラ内のインライン条件で書かれており、後から足した HTML 面が同じ条件を書き写すときに 1 項目落ちて、private 資源の応答が CDN に載る。
- 本文は 404 を返すが、`ETag` や `Last-Modified` は生成済みモデルの値を返している。存在しないはずの資源について、更新の有無が観測できる。
- HTML 面に OGP メタデータを足したとき、`og:title` に repository 名と生成日時が入る。本文が「未生成」と同じ 404 でも、メタデータが存在を漏らす。
- 検索エンジンに載せない方針を決めたが、`robots.txt` / `noindex` が公開面にしか適用されず、条件付きで配信する経路が index される。
- ログに「配信を拒否した資源」の識別子を出す。拒否は正しいが、記録がその存在を残す。

## チェックリスト

新しい応答経路・ヘッダ・派生物を足すときに確認する:

- [ ] 「この資源は誰に見せてよいか」を答える判定が **1 か所**にあり、新しい経路はそれを呼んでいる（条件式を書き写していない）
- [ ] 何も書かなかったときの既定が**安全側**である（配信しない・キャッシュしない・共有しない）
- [ ] 副次チャネル（`Cache-Control` / CORS / `ETag` / OGP / ログ / 検索インデックス）を列挙し、それぞれが判定に従うことを確かめた
- [ ] 見せてはいけない資源の応答が、**存在しない資源の応答と区別できない**（本文・ステータス・ヘッダのすべてで）
- [ ] 判定が false になるケースのテストが、経路ごとにある（1 経路だけ通っても他が漏れることを検出できる）

## 既知の対処パターン

- **判定を型に載せる。** 「配信してよい」と確定した値だけを持つ型（例: `ServableDocument`）を返す関数を通してからでないと応答を組み立てられないようにする。`packages/nest/src/redact/` が「redact を通さないとモデルへ渡せない」を型で不可能にしたのと同じ形。
- **緩和をヘルパに閉じる。** `packages/nest/src/http.ts` は全応答を `no-store` 既定にしている。緩和は「public と判定された資源」を引数に取るヘルパでのみ行い、ハンドラが直接 `Cache-Control` を書かない。
- **同一応答テスト。** 「未生成」と「見せてはいけない」の 2 ケースの応答（status・本文・ヘッダ集合）が完全一致することを 1 本のテストで固定する。
