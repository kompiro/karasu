# TPL-3026: 候補を順に試すルーターは、端点の位置関係ごとに少なくとも 1 つの候補を持つ。柵の corpus は各位置関係を 1 件ずつ含む

## 観点

候補を順に試すルーター（`runRoutingChain`）では、各候補が入力の形に前提条件を持つ。下向きのエッジだけ、2 行以上離れた組だけ、端点の間に行間チャネルがある組だけ、といった条件である。1 つの候補の前提条件は、その候補の中で読めば妥当に見える。問題になるのは**前提条件の和集合**で、和集合が覆わない位置関係があると、その形の入力にはどの候補も成立しない。

never worse の原則により、どの候補も成立しなければ入力は元のまま残る。この穴はエラーにも警告にもならず、「直線のまま描く」という正常な振る舞いとして現れる。

したがって候補を足す・変えるときは、**端点の位置関係を列挙し、各位置関係に少なくとも 1 つの候補があること**を確認する。そして柵の corpus には、各位置関係の入力を 1 件ずつ置く。

端点の位置関係（system / drill-down の行配置の場合）:

| 位置関係 | 例 |
| --- | --- |
| 縦に重なる（同じ行） | 同じ行の 2 枚。間に別のカードがあるかどうかでさらに分かれる |
| 隣の行（下向き / 上向き） | 1 行差 |
| 2 行以上離れる（下向き / 上向き） | skip-layer |
| 片方が枠・側面列にある | in-place 展開の枠、`[external]` の側面列 |

## 想定される失敗モード

- **同じ行の組に候補が無い**（#3026）: channel-L は下向きだけ、corridor と mixed は端点が縦に重なると null、staircase は 2 行以上、側面ガターは遠い側の横 stub が間のカードを横切る。同じ行で間にカードがある組は、どの候補も成立せずに直線のまま残り、間のカードを貫通した。4 つの逆生成モデルで 19 件。
- **柵が green のまま見逃す**: routing-parity の corpus（`examples/`）に同じ行で間にカードがある組が 1 件も無く、貫通 0 の assert は main で green だった。メトリクスは正しく、その位置関係の入力が無かっただけ（TPL-2598 と同型だが、こちらは飽和ではなく位置関係の網羅）。
- **候補ごとのテストは通る**: 各候補の単体テストは、その候補の前提条件を満たす入力しか作らない。前提条件の外側は「この候補の担当ではない」として誰も試さない。

## チェックリスト

候補列に候補を足す・前提条件を変える・候補の順序を変えるときに確認する:

- [ ] 各候補の前提条件（どの位置関係の入力を受け付けるか）を書き出し、上の位置関係の表の各行に少なくとも 1 つの候補があることを確かめた
- [ ] 柵の corpus（実モデルか合成 fixture）が、各位置関係で「直線だと貫通する」入力を 1 件ずつ含む。実モデルに無い位置関係は合成 fixture で足した
- [ ] 足した fixture が修正前のツリーで落ちることを確認した（TPL-2598）
- [ ] 候補が成立せず元のまま残った入力を数えられる（例: 貫通を位置関係別に集計する）。合計だけでは、どの位置関係に穴があるか分からない

## 既知の対処パターン

- **位置関係別に貫通を集計する**: #3026 の計測は、貫通を「端点が縦に重なる組」とそれ以外に分けて数えた（`reports/3026-same-row-chord/measure-3026.mts`）。合計だけを見ると、dify では 17 件のうち 3 件だけが同じ行で、残りは別の類型だと分からない。
- **位置関係ごとの合成 fixture**: 3 つの domain が互いに両方向で依存する fixture は、3 枚が 1 行に並び、両端の組が必ず中央を挟む（どう並べても 1 組は隣にならない）。
- **欠けた位置関係に候補を足す**: 同じ行の組には、行のすぐ上か下の行間チャネルで回る U 字の候補を足した（`trySameRowChannelRoute`、[same-row-channel-route.md](../design/same-row-channel-route.md)）。
