# TPL-2823: 主の配置の後に置く要素も、幅予算の探索と routing chain の両方を通る

## 観点

karasu の配置と配線は、共有の仕組みを何度も足して育ってきた。幅予算の探索（ADR-2593）、チャネルのレーンと予約（ADR-2598）、枠で閉じるチャネル（ADR-3132）、crossing marks（ADR-1859）。どれも「主の配置が置いたカード」と「その間のエッジ」を対象に作られている。

主の配置の**後**に足した要素は、これらの仕組みに自動では乗らない。仕組みが足されたときに、後から置く段まで届いたかを誰も確かめないからである。

- **配置**: 幅予算は `placeNodesInLayers` の行の幅を縛る。後から置く要素が自分の幅を予算で縛らなければ、探索はどの予算でも同じ幅の canvas を採点し、横長の canvas をそのまま選ぶ。探索は最終的な canvas を採点しているので、「探索に入っている」ように見えて、実際には予算が届いていない。
- **配線**: routing chain の各段は、扱わない種類のエッジを `edge.ghost` などで `continue` する。分岐を足した時点では「その種類は短い直線で足りる」という前提があっても、後でその種類の配置が変わると、前提が崩れたことに誰も気づかない。

確認することは 2 つ。**後から置く要素の幅が、探索の候補の予算に応じて変わるか。** **種類で飛ばしたエッジに、飛ばした先で貫通・交差を扱う受け皿があるか。**

## 想定される失敗モード

- **後から置いた行が予算を受け取らない**（#2823）: エンティティビューの ghost は、焦点の枠の後に 1 行で置かれ、外側の枠をその幅まで広げる。Dify `IdentityAccess` は ghost 101 件で 36,053 × 1,372（26 : 1）。どの予算でも同じ幅なので、探索はこの canvas を選んだ。逆生成 3 モデルで、ghost を持つエンティティビュー 82 件のうち 51 件が縦横比の範囲外だった。
- **種類で飛ばしたエッジが受け皿を持たない**（#2823）: ghost の線は ports・channel・lanes・crossing marks のすべてで飛ばされ、相手のカードと ghost を直線で結ぶ。ghost が相手の真下に無いと、線は焦点の枠とカードを斜めに横切り、hop も付かない。分岐を足した時点の前提（ghost は少数で、真下にある）は、1 行に 101 件並んだ時点で崩れていた。
- **数件の前提の流用**: ghost の行は ADR-460 が ghost domain（ふつう数件）のために作り、ADR-1911 がエンティティにそのまま流用した。流用元の前提（件数・位置）を、流用先の入力で測っていなかった。
- **柵が green のまま見逃す**: ghost を描くテストは 1〜2 件の ghost しか作らず、行が焦点の枠より広くならない。TPL-2598 と同じ型で、限界に届く入力が corpus に無かった。

## チェックリスト

- [ ] 主の配置の後に要素を置く段を足す・変えるなら、その段が候補の予算を引数で受け取り、予算で折り返す（または予算に依らないことを理由付きで書いた） [judgment]
- [ ] その段が予算で切られた run は、探索に「まだ広げる余地がある」と返す（`widthBound` など）。返さないと、探索はより広い予算を試さずに止まる
- [ ] routing chain の段に種類で `continue` する分岐を足すなら、飛ばしたエッジがどこで貫通・交差を扱われるかを書いた。扱われないなら、その種類の配置が「直線で足りる」前提を満たし続けることを柵で確かめる [judgment]
- [ ] 別の種類のために作った配置を流用するなら、流用先の実モデルで件数と位置の分布を測り、流用元の前提が成り立つことを確かめた [judgment]
- [ ] 柵のフィクスチャが、後から置く要素を主の配置より広くする件数を含み、修正前のツリーで落ちることを確かめた（TPL-2598） [judgment]

## 既知の対処パターン

- **予算を段に渡す**: #2823 の Design Doc は、ghost の帯を外部ドメインごとの枠に入れ、`max(幅予算, 焦点の枠の幅)` で折り返し、折り返しが予算で切られた run を `widthBound: true` にする。探索の候補列と勝ち方（TPL-2593）は変えない。
- **skip 条件を狭める**: すべての ghost を飛ばす `edge.ghost` の分岐を、受け皿を持たない種類（左右の ghost user / ghost system）だけに狭め、帯の線は chain に通す（#2823 スライス B）。

## 関連テスト

- （#2823 の実装で足す）帯の配置の柵: 外部ドメイン 8 つ以上・ghost 40 件以上のフィクスチャで、エンティティビューと service ビューの canvas が縦横比の範囲に入る。
- （#2823 の実装で足す）routing-parity: 同じフィクスチャで帯の線の貫通 0、共線 0、交差に hop が付く。
