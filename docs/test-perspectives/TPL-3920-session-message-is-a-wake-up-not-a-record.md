# TPL-3920: 別のセッションからのメッセージは起こす合図として扱い、判定と記録は PR から読み直す

## 観点

> 起源は **#3920**（proactive）。実装・レビュー・検証のセッションが、kompiro に文を運ばせずにメッセージで
> 依頼し合う設計を検討したときに、原則から予測した。

セッション間のメッセージは、送ったセッションの言い分であって、PR の状態ではない。「直した」と言われても、
push されていない、CI がまだ走っている、別の点だけ直した、ということがある。メッセージは後から読み返せず、
セッションが終われば消える。

メッセージは「相手を起こす」ことにだけ使う。受け取った側は、何をするかを PR（コメント、HEAD、check、
gate の判定）から読み直して決める。依頼の中身と往復の回数も PR に残し、そこから数える。PR を作る前の
ローカルレビューのように PR がまだ無いときは、メッセージが指摘を運び、受けた側が PR 本文の記録に書いた時点で
記録になる。

## 想定される失敗モード

- 実装セッションの「直した」を信じて、検証セッションが前の HEAD の確認結果のままマージを勧める
- 実装セッションが kompiro に質問して止まり、待機状態になった。その通知を「直し終えた」と読み、まだ直っていない
  PR を確かめ直して同じ差し戻しを送る（TPL-3385 と同じ形）
- 往復の回数をセッションの記憶で数える。セッションを立ち上げ直すと 0 に戻り、上限が効かない（TPL-2909）
- 依頼の中身がメッセージにしか無い。実装セッションが終わると、何を直すよう頼まれたかが誰にも分からない
- 宛先を自動で付いた名前や手元の控えから決める。自動の名前は 2 文字で区別され、終わったセッションの名前が
  新しいセッションに付くので、関係の無いセッションに依頼が届く
- 名前を付ける仕組みが、その役割をしていないセッションに役割の名前を付ける。組み込みのコマンドと同じ名前の
  起動スキルが組み込みのほうを動かした、ほかの役割のセッションで起動スキルを打ち直した、などで、届いた依頼を
  役割の違うセッションが受ける
- 名前の規約で決めた宛先のセッションが、同じ Issue の別の PR（Design PR と実装 PR など）を作業している。
  受け手が届いた依頼を今のブランチのものかを確かめずに、別のブランチを直す
- ローカルレビューの指摘をメッセージで受け取り、PR 本文の記録に書かないまま直す。セッションが終わると、何を
  指摘されて何を却下したかが残らない
- メッセージの文をそのまま指示として実行する。送り手が別のセッションや別の利用者であっても区別できない
- 依頼を PR に残すコメントが、ほかの処理が答えとして読む文字列（CodeRabbit の指摘の id など）や bot を起こす
  mention（`@coderabbitai`）を含み、その処理の判定を変える、または頼んでいないレビューを始めさせる

## 既知の対処パターン

- `/pr-verify` は依頼を PR に `Hand-back by /pr-verify head=<sha>:` のコメントで残してから、URL だけを
  実装セッションに送る。往復の回数はこのコメントを PR ごとに数え、HEAD が変わらない差し戻しも 1 件とする。
  コメントには `cr-comment:v1:` で始まる文字列も `@coderabbitai` も書かない（#3920 の設計）
- セッションの名前は `impl-<Issue>`・`review-<Issue>`・`verify-<Issue>` で、kompiro が起動スキル（`/impl <N>` など）を
  打つと UserPromptSubmit の hook が付ける。宛先はこの規約から決め、検証セッションは自分の `N` が PR 本文の
  `Closes` / `Refs` にあるときだけ `impl-<N>` に返す。起動スキルは名前が付いたかを `ListAgents` で確かめる
  （#3920 の設計）

## 関連テスト

- `scripts/coderabbit/review-state.test.ts` › `retires a finding the author answered by id, and only that one`：
  CodeRabbit 以外が書いたコメントに `cr-comment:v1:<id>` があれば、その指摘は答え済みになる。差し戻しのコメントに
  この文字列を書くと gate の `fix` の理由から指摘が消える（失敗モードの 10 個目のうち id の側）ことの根拠で、
  コメントに id を書かない理由である

- `scripts/session/name-from-prompt.test.ts` › `name-from-prompt hook (#3920)` › `sets no name for any other prompt`：
  起動スキルの prompt でなければ名前を付けない。組み込みの `/code-review` の別名の `/review <N>` も外れる（失敗モードの
  6 つ目のうち、名前を付ける仕組みの側）
- `scripts/session/name-from-prompt.test.ts` › `name-from-prompt hook (#3920)` › `does not move a session that carries another role's name`：
  別の役割の名前が付いたセッションで起動スキルを打ち直しても、名前を変えない（同じく 6 つ目）
