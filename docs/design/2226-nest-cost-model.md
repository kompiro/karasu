# karasu-nest のコストモデルと free-tier quota 提案

- **日付**: 2026-08-02
- **Issue**: [#2226](https://github.com/kompiro/karasu/issues/2226)（親 [#1990](https://github.com/kompiro/karasu/issues/1990)）／gates [#1994](https://github.com/kompiro/karasu/issues/1994)
- **status**: implemented（計測系）／projected（数値）
- **関連 ADR**: [ADR-1990](../adr/1990-karasu-nest-pivot-server-reverse.md) 決定 3（service-paid + strict free-tier quota、水準は本 Issue まで保留）、決定 6
- **関連 TPL**: [TPL-2288](../test-perspectives/TPL-2288-background-work-platform-ceiling.md)

## この文書が答えるもの・答えないもの

ADR-1990 決定 3 は「サービス側が推論費を払い、free-tier に厳しい quota を置く」までを決め、**quota の水準を #2226 の実測まで意図的に空けた**。この文書はその空欄を埋めるために書かれているが、埋め方が 2 段になっている。

- **実測系（このスタックで実装済み）** — 1 回の生成が実際に何トークン・何秒・何ファイルだったかを記録し、集計する経路。`GET /admin/metrics` が数字を返す
- **投影（この文書）** — 実測系がまだ本番データを持っていないので、spike [#1991](https://github.com/kompiro/karasu/issues/1991) の測定値を現行価格に通した見積り

**本番実測がまだ無い理由は技術的なものではない。** ADR-1990 決定 6 により、[#1996](https://github.com/kompiro/karasu/issues/1996)（data-trust）が入るまでこのサービスを他人の private repo に向けない。したがって本番トラフィックは存在しえず、この文書の数値は投影である。投影であることを数値の隣に書くのが本文書の主要な役割で、`pricingAsOf` を全レポートに載せているのも同じ理由による。

## 計測系の形

| 何を | どこに | 鍵 |
| --- | --- | --- |
| 1 回の生成のトークン・秒・ファイル数・redaction 数 | `MetricsStore` | `metrics/krs/v1/<inst>/<owner>/<repo>/<sha>` |
| 生成済みモデルが読まれた回数 | `ReadCounter` | `reads/krs/v1/<inst>/<owner>/<repo>/<YYYY-MM-DD>` |
| 集計と単価適用 | `GET /admin/metrics`（bearer token） | — |

設計上の判断を 3 つだけ記す。

**本文に repo の中身を入れない。** ファイルパスも内容も redaction の値も `.krs` 本文も入れない。owner / repo は**鍵**にだけ置く。metrics store は「実行より長生きし、別のコードから読まれ、誰もこれを repo の内容だと思っていない」という三拍子が揃う場所で、私的データが横に漏れる典型的な経路である（決定 6）。集計レポートが repo 名を 1 つも読まずに作れるのはこの配置のおかげ。

**read の計上は `waitUntil` に載せる。** 生成を `waitUntil` に載せたのが誤りだった（TPL-2288）のと同じ機構を、ここでは正しく使っている。判断基準は「機構が悪い」ではなく「上限と実測時間を突き合わせたか」で、KV への 1 write はミリ秒、`waitUntil` の猶予は約 30 秒。日単位バケットにしているのは KV の同一鍵書き込みレート（毎秒 1 回程度）を避けるためで、そこを超えるトラフィックを持つ repo は既にこの計測が知りたかった答えを出している。**取りこぼしは許容し、水増しはしない** — 数値は quota を主張するために存在するので、高めに出る指標は払えない quota を主張することになる。

**purge に含める。** 決定 6 に「ただしトークン数は残す」という但し書きは無い。本文に repo の内容が無くても鍵に名前がある。

## 投影（#1991 の実測 × 現行価格）

spike #1991 の測定（BC 粒度指示あり、`library` 構成）:

| 指標 | 小（85 ファイル） | 中 | `Dify` 規模 |
| --- | --- | --- | --- |
| 出力トークン | 0.3〜0.5M | — | 数倍 |
| wall-clock | 12〜19 分 | — | 数倍 |
| エージェント数 | 5（BC 指示あり）／9（指示なし） | — | — |

サーバ側パイプライン（#1993）は 3 パス構成で spike のマルチエージェント harness より軽い。入出力を等量 0.4M と置いた保守的な見積りを、`claude-opus-5`（入力 $5/1M・出力 $25/1M、`PRICING_AS_OF = 2026-06-24`）に通す:

| repo 規模 | 入力 | 出力 | 1 回あたり |
| --- | --- | --- | --- |
| 小（〜100 ファイル） | 0.4M | 0.4M | **約 $12** |
| 中（〜200 ファイル、`MAX_FILES_FETCHED` 上限） | 0.8M | 0.6M | **約 $19** |
| 大（上限で切られる） | 0.8M | 0.6M | 約 $19（切り捨て後） |

`MAX_FILES_FETCHED = 200` と `MAX_FILE_BYTES = 200_000` が実質の上限なので、**1 回の生成の上限コストは repo の大きさに比例せず頭打ちになる**。これは quota 設計にとって重要で、最悪ケースが有界であることを意味する。

## #1994 への提案

投影が正しければ 1 回 $12〜19。個人が払える月額を $50〜100 と置くと、**月あたり 3〜6 回**しか回せない。これは「free-tier の quota をどう置くか」ではなく「service-paid が成立するのか」という問いで、ADR-1990 が保留した論点そのものである。

提案:

1. **installation あたり月 1 回**を初期 free-tier とする。「試せる」を満たす最小で、$12〜19 × installation 数がそのまま月額になる。10 installation で $120〜190
2. **同時実行はデプロイ全体で 1**。並列は latency を改善せず、支出速度だけを上げる
3. **同一 SHA の再生成は quota を消費しない**（キャッシュヒットを返す）。ここは既に SHA キーで成立している
4. **上限に達したら 429 と、ローカル逆生成ガイドへの導線**。断り方が導線になっていれば、quota は締め出しではなく分岐になる
5. **`claude-opus-5` を維持する。** ADR-1990 決定 4 が品質を差別化要因に置いており、安いモデルで質を落とすのは「差別化を捨てて費用を下げる」ことになる。落とすなら quota を下げるほうが筋が通る

**BYO-LLM key の再検討について。** ADR-1990 は zero-setup を壊すとして退けた。投影が示すのは「service-paid は installation 数に線形で、10 を超えたあたりで個人の可処分から外れる」ことなので、退けた判断を覆すのではなく**併存**を提案する: free-tier は月 1 回の service-paid、それ以上は BYO key。zero-setup は最初の 1 回で保たれ、continuous な利用だけが鍵を要求される。この判断は #1994 の範囲なので、ここでは選択肢として置くにとどめる。

## 実測に置き換わるまで

`GET /admin/metrics` が本番データで埋まった時点で、この文書の投影表を実測表に差し替え、#1994 の quota を再評価する。判断材料が入れ替わったのに結論が動かないなら、それも記録に値する。

投影のままで ADR に昇格させない。ADR 化するのは #1994 が quota を決めるときで、そのときの根拠は実測か、実測が取れない理由の明示のどちらかである。
