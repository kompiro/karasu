Edge ラベルの段階的開示

線が多い domain レベルの canvas で、どの段に何を出せば読めるか (Umami の UmamiApp drill-down で計測)

spike/3022-edge-label-disclosure Issue #3022 writer 側は Issue #3018

対象は reverse-architecture で起こした Umami モデルの UmamiApp drill-down です。domain 10 個に対して edge が 41 本あり、全部にラベルが付いています。ラベルの長さは中央値 76 文字、最長 135 文字です。

  • 読めない原因は 2 つあります。ラベルが長いこと、そして線が多すぎて短いラベルにも置き場が無いことです。
  • ラベルを短くするだけでは衝突が残ります。現状の衝突は 66 件です。writer 側だけ直すと 18 件、canvas で 24 文字に省略すると 17 件まで減りますが、0 にはなりません。
  • 「重ならずに置けるラベルだけ描く」と衝突は 0 になります。canvas に残るラベルは 41 本中 11 本です。writer 側の修正を重ねると 13 本です。残りは hover で開示します。
  • 既存の examples は 1 バイトも変わりません。56 個の root view で、省略も保留も 1 件も発動しませんでした。

衝突の判定は renderer 自身の関数 (label-placement.ts の countLabel*) をそのまま使っています。「label↔他の線」は実線の edge だけを数えています。薄く描かれる ghost edge の線は、既存の方針 (ADR-2360) どおり障害物に含めていません。V6 と V5 で ghost の線に掛かるラベルは 2 本残ります。

省略だけ (V2) の行が示すとおり、文字数を詰めても label↔card は 17 → 9 までしか減りません。既存の自動配置 (ADR-2048) は約 90px の範囲でしかラベルを動かせず、その範囲に空きが無いためです。

段 0: canvas

下の図はどれも操作できます。線に hover すると、canvas が省略または保留したラベルの全文が tooltip で出ます。domain の card に hover すると、その domain の edge だけが残ります。この振る舞いは app の preview が使うものと同じコードです。

段 1 と段 2: node focus と edge hover

段 1 (node focus): domain の card に hover すると、その domain に出入りする edge だけが残り、他は薄くなります。下は Identity に hover した状態です。

段 2 (edge hover): 線に hover すると、省略または保留されていたラベルの全文が tooltip で出ます。下は Analytics → Identity に hover した状態で、全文は 131 文字あります。tooltip は SVG の外に置いた HTML です。edge は node より先に描かれるので、SVG の中で全文を出すと card の裏に回るためです。

node focus 中に見えるラベル同士の衝突を、node ごとに数えた結果です。対象はその node に出入りする edge のラベルと線、そして全 card です。

線そのものの密度

ラベルを全部消しても (V4)、41 本の線は残ります。有向 edge 41 本は 27 組の domain の間に張られていて、そのうち 14 組は両方向です。domain ごとの本数は次のとおりです。

既存のモデルへの影響

リポジトリの examples/ にある 85 ファイルを調べました。手書きの edge ラベルは 287 本で、最長は 30 文字です。32 文字を超えるものは 0 本、24 文字を超えるものは 15 本でした。

単独でコンパイルできた 56 個の root view について、現状の出力と比べました。40 文字の省略で変わった view は 0 個、auto で変わった view は 0 個、両方で 0 個です。これらの view には今日の時点で衝突が 0 件しかなく、保留されたラベルは 0 本でした。残りの 29 ファイルは、複数ファイル構成か edge を持たないため対象外です。drill-down の各階層は比べていません。

この spike で決めていないこと

  • 既定値。spike は 40 文字 / auto を既定にしています。静的な SVG 出力でもラベルを保留してよいかは別の判断です。静的出力では、保留したラベルは <title> でしか読めません。
  • ghost edge と cyclic edge を配置パスに入れる範囲。spike では auto のときだけ入れています。
  • hop の持ち主を表す属性。spike は hop ごとに属性を足しました。この canvas では SVG が約 9% 大きくなります。hop の描き方は #2956 で設計中です。
  • spike では core のテストが 4,682 件中 2 件落ちます。新しい style property が spec に無いこと、ghost と cyclic の edge を配置パスに入れたことが原因で、どちらも意図した変更の帰結です。
  • ラベルしか持たない edge をクリックしたときの詳細パネル。今は property block を持つ edge だけが開きます。
  • hub の線を既定で薄くする、両方向の 2 本を 1 本にまとめる、といった線側の集約。
